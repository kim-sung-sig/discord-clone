# Java Principal Review 스킬 설계

## 목적

`java-principal-review`는 Java/Spring 백엔드 코드의 작성, 코드 리뷰, 설계 검토, 리팩터링에서 Principal Backend Engineer 관점의 일관된 검토 결과를 제공한다. 기존 `discord-backend-quality-gate`를 대체하지 않으며, 일부 보안·검증 기준이 중복되어도 독립적으로 8개 평가 항목을 완결해 출력한다.

## 활성화

- 명령: `/java-principal-review [파일|디렉터리|diff|계획 문서]`
- 자연어: `Java 코드 검토`, `Spring 코드 리뷰`, `설계 검토`, `리팩터링 검토`, `운영 관점 검토`
- 범위: 일반 Java와 Spring 백엔드. JPA/Hibernate, Kafka, Redis, 분산 시스템 규칙은 관련 의존성·설정·코드가 있을 때만 적용한다.

## 검토 흐름

1. 대상 코드, diff, 계획 문서, 관련 모듈과 테스트를 식별한다.
2. 공통 기준과 활성화된 인프라 규칙팩을 검토한다.
3. 계획 문서가 없거나 명세가 불충분해도 8개 항목 전체를 출력한다. 단, 계획 일치와 최종 평가는 반려다.
4. 1~7번을 총 100점으로 산정하고, 반려 게이트를 별도로 판정한다.
5. 보안·클린코드·성능·모델 기반 개발·개선·운영 발견 사항은 P0/P1/P2로 분류한다.
6. 8번에서 승인, 조건부 승인, 반려와 조치 목록을 확정한다.

## 점수 산정

적용 가능한 세부 항목은 같은 대분류 안에서 균등 배점한다.

- 충족: 세부 항목 배점의 100%
- 부분 충족 또는 개선 필요: 50%
- 미충족 또는 검증 불가: 0%
- 해당 없음: 제외하고 같은 대분류의 나머지 적용 항목에 재배분

| 기준 | 배점 | 평가 범위 |
| --- | ---: | --- |
| 성능 | 15 | N+1, Fetch Join·EntityGraph·BatchSize, 객체·DB 호출·반복 조회, 인덱스·페이징·bounded work |
| 클린코드 | 15 | SOLID/SRP, 이름, early return, 조건 깊이 2 이하, magic number, 중복, 예외 일관성 |
| 모델 기반 개발 | 15 | 업무 용어, 규칙·상태 전이 응집, 불변식, 계층 침범 방지, 변경 영향 경계 |
| 운영 | 15 | 동일 모듈 회귀, 위험 기반 테스트, 장애·동시성·트랜잭션 검증 |
| 보안 | 15 | 인증·인가, 민감정보 로그, 암호화 필요성, XSS·OWASP, 입력 검증·정보 노출 |
| 계획-구현 일치 | 15 | 요구사항·완료 조건별 구현됨/일부/미구현/범위 초과 |
| 개선 사항 | 10 | 근거 있는 최소 변경안, 기대효과·영향도, 개선 기회 누락 |

## 반려와 우선순위

다음은 총점과 무관하게 반려다.

- 계획 문서가 없거나 기능·완료 조건이 명시되지 않음
- 인증 또는 인가 우회
- 중대 보안 취약점
- 데이터 유실·중복·정합성 훼손 가능성
- 운영 장애를 유발할 트랜잭션 경계 또는 오류 처리 누락

- P0: 즉시 조치 필요. 반려 게이트 또는 중대 장애 가능성. 최종 반려.
- P1: 적용 또는 검토 필요. 조건부 승인의 필수 수정 항목.
- P2: 위험도 낮음. 승인 가능하며 백로그에 권장.

P0/P1/P2는 보안, 클린코드, 성능, 모델 기반 개발, 개선, 운영에서만 사용한다. 계획-구현 일치는 요구사항별 상태로만 표현한다.

## 운영 검증

회귀테스트는 기존 테스트가 통과하는지와 함께, 변경한 모듈의 기존 기능이 유지되는지를 확인한다. 관련 모듈의 기존 테스트가 없거나 실행 증거가 없으면 회귀 항목은 미충족이다.

위험이 있는 경우에만 다음 검증을 요구한다.

- 외부 호출: 장애, timeout, 네트워크 지연, retry
- 쓰기 또는 트랜잭션: rollback, lock 경합, 동시 요청, Transactional Outbox 필요성
- 목록 또는 대량 처리: 대량 데이터, 쿼리 수, 페이지 처리
- 권한 또는 입력: 정상, 권한 없음, 잘못된 입력, null

## 인프라 규칙팩

| 규칙팩 | 핵심 기준 |
| --- | --- |
| JPA/Hibernate | N+1, fetch 전략, 페이징과 조인, 쿼리 수, 인덱스, 영속성 컨텍스트, 락·격리 수준 |
| Kafka | 키·파티션 순서, 소비자 멱등성, 재시도·DLQ, 중복, 스키마 호환성, lag, PII |
| Redis | TTL, cache stampede, 무효화, 키·값 크기, eviction, 직렬화, 분산 락 안전성 |
| 분산 시스템·외부 API | timeout 상한, 멱등 retry와 backoff/jitter, circuit breaker, bulkhead, trace ID, 부분 실패, Outbox·Saga |

## 결과 형식

매번 8개 섹션을 모두 출력한다.

```text
# Principal Java Review

대상 / 계획 문서 / 검증 범위
총점: NN/100
최종평가: 승인 | 조건부 승인 | 반려
반려 게이트: 없음 | 목록

1. 성능 — NN/15
2. 클린코드 — NN/15
3. 모델 기반 개발 — NN/15
4. 운영 관점 — NN/15
5. 보안 — NN/15
6. 계획-구현 일치 — NN/15
7. 개선 사항 — NN/10
8. 최종평가

P0 / P1 / P2 조치 목록
실행한 검증 / 검증 불가 항목 / 잔여 위험
```

각 항목에는 적용한 세부 기준, 점수 근거, 파일·라인 또는 검증 증거를 기록한다. 증거 없는 추측은 `검증 불가`로 표현한다.

## 비범위

첫 버전은 채팅에 구조화된 결과만 출력한다. Markdown/HTML 보고서 파일 저장은 이 스킬의 완성본을 검토한 뒤 별도 변경으로 추가한다. Elasticsearch, MQ, S3, Kubernetes 규칙팩도 실제 사용 필요가 확인될 때 추가한다.
