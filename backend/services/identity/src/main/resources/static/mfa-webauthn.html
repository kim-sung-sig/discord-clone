로컬 MFA 연결 확인: 로그인 → TOTP → 패스키 → 보호 API

이 identity 서비스의 http://localhost:포트에서 여세요. 로그인은 로컬 boot 서버(legacy-auth 프로필)의 실제 /api/auth/login을 사용하고, 토큰은 이 페이지 메모리에만 있으며 새로고침하면 사라집니다. 운영 계정·운영 토큰을 넣지 마세요.

토큰 없음 (로그인 필요)

1. 로그인 (실제 legacy-auth 발급자)

boot 계정 저장소가 in-memory이면 boot를 재시작할 때 계정이 사라집니다. 로그인은 분당 2회로 제한됩니다.

2. TOTP 등록과 추가 인증

인증 앱에 등록할 secret (이 화면에서만 표시, 확인 성공·추가 인증·로그인·지우기 때 지움. 확인 없이 5분이 지나면 서버에서 무효가 되며 재시작 API는 없음):

등록 확인에 쓴 코드는 재사용할 수 없습니다. 추가 인증에는 다음 30초 코드가 필요합니다. 이미 등록된 계정이면 등록 시작은 409로 거부되며 바로 추가 인증으로 진행합니다. 잠금 해제와 재설정은 최근 5분 내 패스키 인증이 필요합니다. 복구 코드는 제공하지 않습니다.

3. 패스키 등록과 추가 인증

등록 후 인증 options를 요청하기 전 10초를 기다리세요. PIN·생체 확인을 취소하면 다시 시작해야 합니다.

3-1. 내 패스키 목록과 삭제

등록된 패스키가 없습니다.

    목록은 이 계정의 패스키 이름·등록/마지막 사용 시각·id 앞부분만 보여 줍니다(공개키·attestation은 서버가 보내지 않음). 삭제에는 최근 5분 내 MFA 토큰이 필요합니다. 마지막 패스키는 활성 TOTP가 있고 실패 횟수가 5 미만일 때만 삭제할 수 있습니다. 삭제는 서버에서 즉시 반영되고 되돌릴 수 없습니다.

    4. 같은 사용자의 보호 API 확인

    브라우저 지원을 확인하고 있습니다.

    개발자 도구에서 눈여겨볼 것
    • 로그인·회원가입 요청은 credentials: omit이라 로그인 서버의 refresh 쿠키가 저장되지 않습니다. 이 페이지는 refresh를 사용하지 않습니다.
    • identity 요청에는 Authorization 헤더가 있고, WebAuthn options와 complete는 같은 세션 쿠키(진행 중 ceremony 결속 전용)를 사용합니다.
    • 등록은 navigator.credentials.create, 인증은 navigator.credentials.get이며 options의 rp.id = localhost, userVerification = required를 확인하세요.
    • 토큰·비밀번호·코드·secret은 상태 문구에 출력하지 않습니다. Network 내보내기에는 포함되므로 공유하지 마세요.
